# Security Specification — GetFitNow Event

## 1. Data Invariants
1. **Strict PII Isolation & Authenticated Member Access**: `registrations` and `members` contain Personally Identifiable Information (`email`, `firstName`, `lastName`, `phone`, `notes`). Unauthenticated visitors can NEVER `get`, `list`, `create`, `update`, or `delete` documents in `/events`, `/registrations`, or `/members`. Signed-in, non-anonymous users (`hasAuthenticatedEmail()`) can only read their own `/registrations` (where `email == request.auth.token.email.lower()`) and read/update their own basic `/members/{emailKey}` fields (`firstName`, `lastName`, `phone`, `goal`, `photoUrl`), while coach `notes` and `followUpStatus` remain strictly coach-controlled. Only an active Coach (`isAdmin()`) can list or manage all members and registrations.
2. **Members Cannot Create Events**: `/events` `create`, `update` (metadata), and `delete` are strictly gated to `isAdmin()`. Members can never create or alter event definitions.
3. **Configurable Per-Event Booking Cutoff (`bookingCutoffMinutes`)**: Events do not auto-cancel or close 1 hour before start by default (`bookingCutoffMinutes == 0`). Coaches can optionally configure `bookingCutoffMinutes` (`0..10080`) on event creation/update; member registrations are blocked once `request.time >= event.startAt - duration.value(event.get('bookingCutoffMinutes', 0), 'm')` (enforced in both client UI and `firestore.rules`).
4. **Capacity & Atomicity**: A registration cannot be created if `event.isUnlimitedCapacity == false && event.registeredCount >= event.maxCapacity` or `event.status != 'published'`. Creating a registration and incrementing `event.registeredCount` MUST happen in the same atomic batch (`getAfter()` + `existsAfter()`). Likewise, an authenticated member can only cancel their own upcoming (`request.time < eventStartAt`) confirmed registration (`status: 'confirmed' -> 'cancelled'`, and `paymentStatus: 'paid' -> 'refunded'` + `/payments/{id}.status = 'refunded'` if paid) atomically with decrementing `events/{eventId}.registeredCount` by `-1`.
5. **Duplicate Prevention & Re-booking**: Registration IDs follow `${eventId}__${emailKey}`. Only an active Coach (`isAdmin()`) or the authenticated owner performing end-of-session validation, self-cancellation, or re-booking a previously cancelled registration (enforcing all creation capacity/cutoff/payment checks) can update `/registrations/{id}`; an adhérent cannot overwrite an active confirmed booking or register twice for the same event.
6. **Immutable Audit Fields & Server Timestamps**: `createdAt` and `updatedAt` must equal `request.time`. `createdBy` and `createdAt` cannot be modified after creation.
7. **Privilege Escalation & Two-Tier Coach RBAC (`coach` vs `coach_admin`)**: Only verified primary Coach (`davidfrosio@hotmail.fr`) or an active document in `/admins/{uid}` (`active == true`) passes `isCoach()`, while team/admin management (`isCoachAdmin()`) additionally requires `role == 'coach_admin'`. Users cannot self-assign `coach` or `coach_admin` roles in `/admins`. New coach invitations (`/adminInvites`) and approved access requests (`/coachAccessRequests`) strictly default to `role == 'coach'` (non-admin). Only an active `coach_admin` can accept/reject new coach requests, invite/activate/deactivate/delete coaches, or accept/refuse promoting a standard `coach` to `coach_admin`. Disabling (`active: false`) or deleting an `/admins/{uid}` document immediately revokes all coach and admin permissions.
8. **Coach & Member Profile Photos & Custom Disciplines**: Each active coach can update their own non-privileged info sheet fields (`displayName`, `phone`, `specialty`, `city`, `region`, `certifications`, `bio`, `photoUrl`, `updatedAt`) on `/admins/{uid}`. Members and coaches can store size-bounded profile photos (`photoUrl <= 80000` chars). `/disciplines/{slug}` holds non-PII discipline names and color keys, with writes strictly gated to `isAdmin()`.
9. **Targeted Coach Registration Notifications**: Creating `/coachNotifications/{notificationId}` is permitted only atomically inside the same batch as a brand-new `/registrations/{registrationId}` creation (`!exists` before, `existsAfter` after), with `coachUid` strictly matching `events/{eventId}.createdBy`. Only the targeted coach (`coachUid == request.auth.uid && isAdmin()`) can read, mark as read, or delete their notifications.
10. **End-of-Session Member Validation Notifications & Self-Validation**: `/memberNotifications/{registrationId}` can only be created once `request.time >= eventEndAt` for a `confirmed`, unvalidated (`attended == false`) registration belonging to the target member. A signed-in member can only read/delete their own `/memberNotifications`, mark them as read, or atomically self-validate their ended session (`attended == true && memberValidated == true` on `/registrations/{registrationId}` paired with `validated == true && read == true` on `/memberNotifications/{registrationId}`).
11. **Atomic Event Likes (`/eventLikes/{eventId}__{uid}` + `events.likesCount`)**: Every like document uses deterministic ID `${eventId}__${request.auth.uid}` and stores only non-PII fields (`eventId`, `userId`, `createdAt`). Creating or deleting a like MUST atomically increment or decrement `/events/{eventId}.likesCount` by `±1` and update `lastLikeId` in the same batch (`existsAfter`/`getAfter`). Unauthenticated users cannot like events, and a user can only read/create/delete their own like documents.
12. **Verified Post-Event Reviews & Comments (`/eventReviews/{eventId}__{emailKey}`)**: Publicly readable reviews contain zero PII (`authorName` uses first name + last initial, `emailKey` is an opaque hash). Only an authenticated participant with a matching `confirmed` registration in `/registrations/{registrationId}` whose session has already reached its end time (`request.time >= eventEndAt`) AND whose attendance is validated (`attended == true`) can create or update a review (`rating` 1..5, `comment` 3..800 chars) on a `published` event. Reviews and ratings are hidden in the client until the event end time is reached and the session is validated. Only the review author (`authorUid == request.auth.uid`) can update or delete their review (coaches `isAdmin()` may moderate/delete).
13. **Private Coach–Member Messaging (`/conversations/{coachUid}__{memberEmailKey}` + `/messages/{messageId}` & `/coachDirectory/{coachUid}`)**: `/coachDirectory` contains only non-PII active coach display profiles (`uid`, `displayName`, `specialty`, `city`, `region`, `bio`, `photoUrl`, `active`) writable exclusively by active coaches. Conversations use deterministic 1-to-1 ID `${coachUid}__${memberEmailKey}`. Only the participating coach (`coachUid == request.auth.uid`) or the participating member (`memberEmail == request.auth.token.email.lower()`) can read, list, or delete a conversation and its messages (message deletes enforce the parent Master Gate). Every `/messages/{messageId}` create MUST atomically create or update the parent `/conversations/{conversationId}` in the same batch (`getAfter()`), verifying `senderUid == request.auth.uid`, `senderEmail == request.auth.token.email.lower()`, server `request.time` timestamps, and valid increment of the recipient's unread counter. Message core content (`text`, `senderUid`, `senderEmail`, `createdAt`, context) is immutable once sent; participants may only toggle their own reaction flag (`likedByCoach` for the coach, `likedByMember` for the member) with `updatedAt == request.time`.
14. **Private Personalized Member Weekly Schedules (`/memberSchedules/{sessionId}`)**: Custom coaching/training sessions stored in `/memberSchedules` contain private member training details (`memberEmail`, `title`, `discipline`, `notes`, `location`, `startAt`, `durationMinutes`, plus optional `objective` and bounded `exercises` list up to 25 items). Only active coaches (`isAdmin()`) can create, edit, or delete sessions (`createdByRole == 'coach'` and `createdByUid == request.auth.uid`). The target authenticated member (`memberEmail == request.auth.token.email.lower()`) can only read/list their own sessions, complete payment for paid coach-assigned sessions, and toggle `completed` on unlocked/paid sessions. `memberEmail`, `memberEmailKey`, `createdByUid`, `createdByRole`, and `createdAt` are immutable after creation, `updatedAt == request.time`, and all strings/durations (`15..240`) and exercise parameters are strictly bounded.
15. **Coach-Only Exercise Library (`/exercises/{exerciseId}`)**: All read (`get`/`list`) and write (`create`/`update`/`delete`) operations on `/exercises` are strictly restricted to active coaches (`isAdmin()`). Every exercise validates `name` (2..100), `category` (`'strength' | 'running' | 'mobility'`), bounded `targetObjectives` (`size() <= 8`), `description` (<= 500), `defaultParams` (`repetitions` 0..500, `durationSeconds` 0..7200, `setsOrRounds` 1..50, `intraSetPauseSeconds` 0..600, `restBetweenRoundsSeconds` 0..1800), immutable `createdBy == request.auth.uid`, and server timestamps (`request.time`).

## 2. "Dirty Dozen" Attack Payloads
1. **Late Booking (After Configured Cutoff or Start)**: Member submits `registrations/{id}` when `request.time >= event.startAt - duration.value(event.get('bookingCutoffMinutes', 0), 'm')` -> `PERMISSION_DENIED`.
2. **Overbooking Beyond Capacity**: Member submits `registrations/{id}` when `registeredCount == maxCapacity` -> `PERMISSION_DENIED`.
3. **Unpaired Registration (No Event Increment)**: Member creates `registrations/{id}` without atomically incrementing `events/{eventId}.registeredCount` -> `PERMISSION_DENIED`.
4. **Fake Event Counter Inflation**: Member updates `events/{eventId}.registeredCount` without creating a valid registration in the same batch -> `PERMISSION_DENIED`.
5. **Unauthenticated & Cross-Member PII Scraping**: Unauthenticated user lists `/events`, or non-coach signed-in user attempts to `list` another member's `/registrations` or `/members`, or any `/admins` / `/coachAccessRequests` -> `PERMISSION_DENIED`.
6. **Shadow Field Injection**: Payload adds an unexpected field (`isVip: true` or `role: 'admin'`) to `events`, `registrations`, `members`, `admins`, `coachAccessRequests`, or `adminInvites` -> `PERMISSION_DENIED` (`hasOnly` check).
7. **Self-Assigned Admin or Tampered Coach Notes**: Non-admin user attempts `setDoc` on `/admins/{uid}` without a matching pending `/adminInvites/{emailKey}`, or a member tries to alter `followUpStatus`/`notes` on their `/members` profile -> `PERMISSION_DENIED`.
8. **Spoofed Timestamp**: Client sends a custom past/future Date instead of `serverTimestamp()` for `createdAt`/`updatedAt` -> `PERMISSION_DENIED`.
9. **Resource Poisoning (Oversized Strings / Photos / IDs)**: Client sends 5KB string in `firstName`/`title` or oversized `photoUrl > 80000` chars -> `PERMISSION_DENIED` (`.size()` & `isValidId()`).
10. **Cancelled Event Registration**: Member attempts to register for an event with `status == 'cancelled'` -> `PERMISSION_DENIED`.
11. **Disabled Coach Action**: A coach whose `/admins/{uid}.active` is `false` attempts to create/edit events or read all registrations -> `PERMISSION_DENIED`.
12. **Unverified Admin Email Spoof**: User with `email_verified == false` attempts to claim bootstrapped admin (`davidfrosio@hotmail.fr`) or email-based `/adminInvites` -> `PERMISSION_DENIED`.
13. **Unpaired Like Counter Inflation**: User increments `events/{eventId}.likesCount` directly without creating `/eventLikes/{eventId}__{uid}` in the same batch, or passes another user's `userId` -> `PERMISSION_DENIED`.
14. **Premature, Unvalidated, or Unregistered Event Review**: User attempts to create `/eventReviews/{reviewId}` without a confirmed registration for that event, before validating their session (`attended == false`), before the session reaches its end time (`request.time < eventEndAt`), or for another user's registration -> `PERMISSION_DENIED`.
15. **Review Author Tampering / Shadow Rating**: User attempts to edit someone else's review or inject `rating: 99` or raw `email` shadow fields into `/eventReviews` -> `PERMISSION_DENIED`.
16. **Cross-User Conversation Eavesdropping, Orphaned Message Injection & Reaction Spoofing**: User attempts to read/list/delete another member's or another coach's `/conversations` or `/messages`, send a message with spoofed `senderUid` / `senderRole: 'coach'`, create a `/messages/{id}` without atomically updating `/conversations/{id}` (`lastMessageAt == request.time`), edit message `text`/`createdAt` while liking, or flip the other participant's `likedBy*` flag -> `PERMISSION_DENIED`.
17. **Unauthorized Personal Schedule Creation/Tampering**: Member attempts to create a `/memberSchedules/{id}` document (even for their own email with `createdByRole: 'member'` or spoofed `'coach'`), edit title/notes/date/exercises, delete a session, read another member's schedule, or submit out-of-range `durationMinutes` or >25 `exercises` -> `PERMISSION_DENIED`.
18. **Non-Coach Exercise Library Access & Parameter Poisoning**: Unauthenticated visitor or standard member attempts to read/create/edit/delete `/exercises/{id}`, or sends invalid `category`, negative/excessive `repetitions`/`setsOrRounds`, or shadow fields in `defaultParams` -> `PERMISSION_DENIED`.
19. **Unpaid Personalized Program Bypass & Premature/Tampered VMA Test**: Member attempts to create a `/trainingPrograms/{id}` themselves, lower `priceCents`, submit a VMA test before paying (`paymentStatus == 'pending'`) or before `startAt` (Day 1), inject `paymentStatus: 'paid'` without valid card checkout fields, or mark a paid `/memberSchedules/{id}` session completed before payment -> `PERMISSION_DENIED`.
20. **Cross-Member Training Program Access**: Member attempts to `get`, `list`, pay, or write VMA results on another member's `/trainingPrograms/{id}` -> `PERMISSION_DENIED`.

## 3. Additional Invariants
16. **Running Programs (`/trainingPrograms/{programId}`) & Coach Sessions (`/memberSchedules/{sessionId}`) — Paid or Free (Offert)**: Every personalized running program (`distance in ['5km', '10km', '21km', '42km']`, optional `level in ['beginner', 'regular', 'experienced']`, `durationWeeks` matching distance/level: 5km 10/8w, 10km 12/10w, 21km 14/12w, 42km 16/14w, `sessionsPerWeek in 2..6`, `targetTimeSeconds`, either free `isPaid == false && priceCents == 0 && paymentStatus == 'free'` or paid `isPaid == true && priceCents >= 100`) is created and deleted exclusively by active coaches (`isAdmin()`). Only active coaches or the target member (`memberEmail == request.auth.token.email.lower()`) can read/list a program. Members cannot alter price, `isPaid`, distance, level, durationWeeks, schedule frequency, or target time; they may only: (a) pay for a pending paid program (`paymentStatus: 'pending' -> 'paid'` via card with `cardLast4.size() == 4`, `paymentReference.size() >= 6`, `paidAt == request.time`, or select `'onsite'` when allowed), (b) submit their Day 1 VMA evaluation once paid or free (`isPaid == false || paymentStatus == 'paid'`) and on/after `startAt` (`vmaKmh` in `6.0..26.0`, `vmaTestStatus == 'completed'`, `vmaTestedAt == request.time`), and (c) toggle completion keys in `completedSessionKeys` (`size() <= 100`). Similarly, coach-created standalone personalized sessions in `/memberSchedules` can be either free (`isPaid: false`, `priceCents: 0`, `paymentStatus: 'free'`) or paid (`isPaid: true`, `priceCents >= 100`), requiring member payment before completion only when `isPaid == true`.
